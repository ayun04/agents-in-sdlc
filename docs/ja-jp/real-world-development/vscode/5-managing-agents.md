GitHub Copilot を agent mode で使うと、コードベースを調べ、変更を提案し、ファイルを編集してコマンドを実行するなど、自律的に作業します。VS Code の Copilot Chat は自分のマシンでリアルタイムに作業するため、ツールの呼び出しやファイルの編集を逐一確認できます。差分をインラインでレビューし、個々の変更を採用または取り消し、フォローアップのプロンプトで作業を調整したり追加したりできます。エディターを離れる必要はありません。

この演習では、次の操作を行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイルの編集をレビューして採用します。
- セッションの途中でエージェントに指示を追加し、高コントラスト モードとライト モードの切り替えを実装します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用のカスタム エージェントが、高コントラスト モードを実装しています。作業中、デザイン チームから、既定のテーマが暗すぎると感じるユーザー向けにライト モードも追加してほしいという依頼がありました。新しい会話を始める代わりに、進行中のセッションに指示を追加して機能を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが実行する手順が表示されます。調べたファイル、実行したコマンド、提案した編集を確認できます。ファイルの編集は差分と **Keep** / **Undo** の操作とともにチャットに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中、チャットをスクロールしてツールの呼び出しを確認します。ファイルの読み取りや編集、実行を求められたターミナル コマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がチャットに表示されます。
   - **Keep** を選択すると変更を採用します。
   - **Undo** を選択すると変更を取り消し、エージェントが再度作業できるようにします。
4. チャットの上部にある **Files changed** インジケーターを開くと、このセッションで変更されたファイルをまとめて確認できます。

> [!NOTE]
> ターミナル コマンドの実行などに許可が必要な場合、エージェントは **Allow** を表示して一時停止します。実行してもよいコマンドだけを許可してください。

5. エージェントが高コントラスト モードの実装を終えるまで待ちます。変更の概要を説明する最終メッセージが表示されます。

## エージェントにライト モードを追加するよう指示する

高コントラスト モードができたら、同じ会話でライト モードの切り替えを追加します。同じチャット セッションを続けると、エージェントは前の作業で変更したコンポーネント、スタイルの方針、local storage を使った設定の保存方法など、既存のコンテキストを引き継ぎます。

1. Copilot Chat の入力欄に、次のフォローアップ プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは既存の変更を調べ、ライト モードの変更を提案します。
3. 高コントラスト モードの場合と同様に、新しい編集を確認します。各差分で **Keep** または **Undo** を使います。
4. エージェントが意図しない方向に進んだ場合 (たとえば、好みに合わない方法で切り替え UI をリファクタリングする場合) は、チャット入力欄の隣にある **Stop** ボタンで停止し、補足のメッセージを送信します。

> [!TIP]
> 作業中のセッションに指示を追加する方が、最初からやり直すよりも速くなります。フォローアップ プロンプトで、「CSS を簡潔にし、セレクターの重複ではなく CSS 変数を使う」のように調整を依頼できます。「3 つ目の切り替えを追加せず、既存の設定パネルにライト モードを統合する」のように方針を修正したり、「両方の切り替えにキーボード ショートカットも追加する」のように範囲を広げたりすることもできます。

## 変更されたファイルをレビューする

コミットする前に、エージェントが変更したすべてのファイルを確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタム エージェントのアクセシビリティ パターン、ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保存が反映されていることを確認します。
4. 問題がなければ **Source Control** パネルで変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat agent mode で進行中のセッションを監視して方向付けました。ファイルの編集を確認して採用または取り消し、フォローアップ プロンプトでコンテキストを保ったまま作業を拡張しました。

このレッスンでは、エージェントの作業をリアルタイムで監視し、個々の編集を採用または取り消し、フォローアップ プロンプトでセッションの途中に指示を追加しました。
